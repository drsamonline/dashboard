Leaderboard

Two axes, because one is not enough: quality is the heuristic score, activity is how much changed recently. A big quiet repo and a small thriving one are not comparable on either alone.

System health

Two numbers that used to be one-off answers in a session: how many apps are DECIDED BUT UNSPECCED, and the run record (which flags any run that touched a file which lost lines).

Metadata completeness

Five metadata booleans per repository — a description, a licence, a homepage, Pages, and not archived — not build quality: a repo whose build failed on its latest run still scores 5/5. How many repos satisfy each system rule — topics, a licence, a changelog, a test, a description. A bar at 100% means every repo passes that rule; a short bar is the work list.

Categories

Repos grouped by what they are — kit, app, system, meta — with the count in each. It answers "how much is tooling versus product".

Actions budget

GitHub Actions minutes used this month against the free allowance. Everything here is built to run inside it — no paid runners.
